## 2024-03-24 - V8 Array vs Uint8Array and String Indexing Overhead
**Learning:** In tight loops generating strings from random bytes, dynamically resizing arrays (`stack.push`) adds severe overhead compared to pre-allocated `Uint8Array`. Additionally, method calls like `buf.readUInt8(i)` and `chars.charAt()` incur significantly more penalty than direct bracket property access (`buf[i]` and `chars[...]`), even when compiling TypeScript down to JavaScript. Property access overhead can also be measurably reduced by caching string lengths (`chars.length`) locally.
**Action:** Always pre-allocate fixed-length buffers using `Uint8Array` over standard dynamically resizing arrays when collecting random bytes. When dealing with Buffers or strings in performance-critical inner loops (especially `for` loops bounded by random entropy generation), use cached lengths and direct bracket indexing instead of method wrappers.
